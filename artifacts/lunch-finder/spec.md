# lunch-finder spec

## 개요

직장인이 매일 점심을 고를 때 겪는 결정 피로와 예산 불안을 해소하는 개인 큐레이션 도구.
내가 직접 등록한 식당 중 1만원 이하 메뉴가 있고 최근 방문하지 않은 곳을 자동으로 골라 보여준다.

## 범위

### 포함
- 추천 화면: 조건에 맞는 식당 2-3개를 즉시 표시
- 식당 CRUD: 카카오 검색으로 기본 정보 채우고 메뉴·가격은 직접 입력
- 방문 기록: 카드 열면 자동으로 오늘 방문 처리
- 1만원 이하 필터: 등록된 메뉴 중 하나라도 10,000원 이하인 식당만 추천 대상
- 최근 방문 제외: 3일 이내 방문한 식당은 추천에서 후순위
- 데이터 브라우저 로컬 저장: 서버 없이 이 기기에만 보존

### 제외
- 서버 DB / 멀티 기기 동기화 — 개인 도구로 단일 기기면 충분
- 자동 가격 크롤링 — 법적 리스크, 유지 비용
- 배달 기능 — 배민/쿠팡이 이미 담당
- 리뷰·별점 — 혼자 쓰는 도구에 불필요
- 소셜 공유 — 목적 외

## 시나리오

### 1. 추천 화면 — 정상 케이스

- **Given** 1만원 이하 메뉴가 하나 이상 있는 식당이 4개 이상 등록되어 있고, 그 중 최근 3일 이내에 방문한 곳이 2개 이하
- **When** 앱 메인 화면 진입
- **Then** 최근 3일 미방문 + 1만원 이하 메뉴 보유 식당 중 2-3개 카드가 표시된다

성공 기준:
- [ ] 각 카드에 식당 이름, 카테고리, 1만원 이하 최저 메뉴명과 가격이 표시된다
- [ ] 최근 3일 이내 방문 식당은 카드 목록에 나타나지 않는다
- [ ] 1만원 이하 메뉴가 없는 식당은 카드 목록에 나타나지 않는다

### 2. 추천 카드 열기 → 자동 방문 기록

- **Given** 추천 카드 2개가 표시된 메인 화면
- **When** 카드 A를 탭해 상세 화면으로 이동
- **Then** 식당 A의 전체 메뉴·가격 목록이 표시되고, 오늘 날짜로 방문 기록이 자동 생성된다

성공 기준:
- [ ] 상세 화면에 식당의 전체 메뉴(이름·가격) 목록이 표시된다
- [ ] 뒤로 가기 후 메인 화면을 새로 열면 식당 A 카드가 추천 목록에서 사라진다 (3일 이내 방문 처리)
- [ ] 같은 날 같은 식당을 두 번 열어도 방문 기록은 하루 1건만 생성된다

### 3. 다음 추천

- **Given** 추천 카드 2-3개가 표시된 메인 화면
- **When** "다음 추천" 버튼 클릭
- **Then** 이전에 보이던 카드와 다른 식당들로 교체된다

성공 기준:
- [ ] 이전 추천 목록에 있던 식당은 새 추천 목록에 포함되지 않는다
- [ ] 후보 식당이 부족하면 가장 오래된 방문 순으로 채운다

### 4. 추천 가능 식당 없음

- **Given** 등록된 모든 식당이 최근 3일 이내에 방문됐거나, 모두 1만원 초과 메뉴만 있음
- **When** 앱 메인 화면 진입
- **Then** "최근 방문한 곳만 있어요. 가장 오래된 순으로 보여드립니다" 안내와 함께 방문 일자가 가장 오래된 식당 카드가 표시된다

성공 기준:
- [ ] 위 안내 문구가 화면에 나타난다
- [ ] 가장 오래 전 방문한 식당 카드 2-3개가 표시된다

### 5. 등록 식당 없음 (첫 접속)

- **Given** 등록된 식당이 0개인 상태
- **When** 앱 메인 화면 진입
- **Then** 빈 상태 안내와 식당 추가 버튼이 표시된다

성공 기준:
- [ ] "아직 등록된 식당이 없어요" 또는 동등한 안내 문구가 표시된다
- [ ] 화면에 식당 추가로 이어지는 버튼이 표시된다

### 6. 식당 추가 — 카카오 검색

- **Given** 식당 추가 화면
- **When** 검색창에 식당 이름을 입력하고 결과 목록에서 하나를 선택
- **Then** 식당 이름·주소·카테고리가 자동으로 채워진 상태로 메뉴 입력 폼이 표시된다

성공 기준:
- [ ] 검색어 입력 시 카카오 로컬 검색 결과 목록이 나타난다
- [ ] 결과 항목 선택 시 이름·주소·카테고리 필드가 자동 채워진다
- [ ] 이름·주소·카테고리는 자동 채워진 후에도 직접 수정 가능하다

### 7. 메뉴 추가

- **Given** 식당이 선택된 상태의 메뉴 입력 폼, 메뉴가 0개
- **When** 메뉴명 "된장찌개"·가격 "8500" 입력 후 추가
- **Then** 메뉴 목록에 "된장찌개 8,500원"이 나타난다

성공 기준:
- [ ] 메뉴명이 비어 있으면 추가 버튼이 비활성 또는 에러가 표시된다
- [ ] 가격이 비어 있거나 0 이하이면 추가 버튼이 비활성 또는 에러가 표시된다
- [ ] 저장 후 식당 상세 화면에서 해당 메뉴가 표시된다

### 8. 메뉴 삭제

- **Given** 식당 상세 화면, 메뉴 2개 표시 중
- **When** 메뉴 중 하나의 삭제 버튼 클릭
- **Then** 해당 메뉴가 목록에서 사라지고 1개가 남는다

성공 기준:
- [ ] 삭제 후 메뉴 수가 1개 줄어든다
- [ ] 마지막 메뉴를 삭제하면 "메뉴 없음" 상태로 빈 목록이 표시된다

### 9. 식당 삭제

- **Given** 식당 목록 또는 상세 화면
- **When** 식당 삭제 버튼 클릭
- **Then** 식당과 해당 식당의 모든 메뉴·방문 기록이 제거되고 목록에서 사라진다

성공 기준:
- [ ] 삭제된 식당은 추천 화면과 식당 목록 어디에서도 나타나지 않는다
- [ ] 삭제 전 확인 단계(예: "정말 삭제할까요?")가 존재한다

### 10. 위치 권한 거부

- **Given** 브라우저 위치 권한이 거부된 상태
- **When** 식당 추가에서 카카오 검색 시도
- **Then** 위치 기반 정렬 없이 검색어 기반 전국 결과가 표시된다

성공 기준:
- [ ] 위치 권한 없이도 이름 검색은 동작한다
- [ ] 위치 권한이 없음을 사용자에게 알리는 안내가 표시된다

## 불변 규칙

**데이터 격리**: 모든 데이터(식당·메뉴·방문 기록)는 이 브라우저 이 기기에만 저장된다. 외부 서버로 전송되지 않는다.

**가격 기준**: 1만원 이하 판정은 식당에 등록된 메뉴 중 하나라도 10,000원 이하인 경우. 메뉴가 0개인 식당은 추천 대상에서 제외된다.

## 의존성

- 카카오 로컬 REST API (식당 검색용, 앱키 발급 필요)
- 브라우저 Geolocation API (선택적 — 거부 시 검색어 기반으로 폴백)
